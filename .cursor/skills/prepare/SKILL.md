# Prepare

## Purpose

Prepare the project for automated execution.

**Assume that task generation has already been completed by `@prepare-prompt`.**

**Do not generate new tasks.**

Instead:

- synchronize task metadata;
- assign skills;
- assign rules;
- optimize execution order;
- prepare execution plan;
- generate `prepare-report.md`.

**`prepare` must consume the dependency graph generated by `@verify-todo`.**

This skill never executes project tasks, never modifies source code, and never performs scientific analyses.

Follow project rules: **validation-first**, **missing-data-policy**, **method-decision-tracking**, **scientific-integrity**, **task-status**, **artifact-registry**.

Pair with `@do` for execution. Upstream: `@prepare-prompt` → `@verify-todo` → **`@prepare`**.

## Inputs

Inspect:

- `todo.md`
- every task under `./todo/` (already created)
- `dependency-graph.md` / `dependency-graph.mmd` (from `@verify-todo`)
- `method-decision.md` (if present)
- `docs/artifact-registry.md`
- available project rules (`.cursor/rules/`)
- available project skills (`.cursor/skills/`)
- project documentation

If `./todo/` is empty or tasks are missing, **stop** and direct the user to `@prepare-prompt` — do not invent tasks here.

## Workflow

```
Prepare:
- [ ] Phase 0: @verify-todo — consume/regenerate graph; stop if failure
- [ ] Phase 1: Inventory existing tasks (no new task creation)
- [ ] Phase 2: Synchronize task metadata (todo.md ↔ ./todo/)
- [ ] Phase 3: Assign skills and rules
- [ ] Phase 4: Optimize execution order from verify-todo graph
- [ ] Phase 5: Write execution plan + prepare-report.md
- [ ] Phase 6: Readiness check
```

If `@verify-todo` returns **failure** (Blocking or failed repair), terminate prepare immediately. Propagate failure to any parent skill.

**Graph ownership:** `@verify-todo` is the only skill that constructs and validates the task dependency graph. Prepare must **not** rebuild or re-validate that graph — only **consume** `dependency-graph.md` / `dependency-graph.mmd`.

---

## Phase 0 — Verify-todo graph

Invoke `@verify-todo` so the dependency graph is current.

Then load:

- `dependency-graph.md`
- `dependency-graph.mmd`

If artifacts are missing after a successful verify-todo, fail prepare.

---

## Phase 1 — Inventory existing tasks

**Do not generate new tasks.**

Determine from existing `./todo/` + `todo.md`:

- project objectives (from docs / existing task titles)
- Status of each task (`TODO` | `READY` | `RUNNING` | `BLOCKED` | `FAILED` | `RECOVERABLE` | `COMPLETED` | `SKIPPED`)
- incomplete vs COMPLETED / SKIPPED
- declared dependencies (already in task specs)
- required computational environments (from task metadata)

Report gaps (orphans, incomplete `<Task>` fields) — fix metadata only; if a required task is absent, recommend `@prepare-prompt`.

---

## Phase 2 — Synchronize task metadata

Synchronize between `todo.md` and `./todo/*.md`:

- ensure every `./todo/` file is linked exactly once from `todo.md`;
- sync Status, Depends on, Outputs, and links;
- preserve manually written descriptions and `Note:` / `User:` / `## Manual notes`;
- align `<Task>` XML-like fields with the Execution metadata table when both exist.

Report orphaned TODO files and orphaned TODO entries — do **not** create new task files to resolve orphans (except fixing links/metadata on existing files). Creating missing work items is `@prepare-prompt`'s job.

### Linking convention

```markdown
- [ ] **T-2.1** Run dataset audit …
  - Subtask: [todo/T-2.1-dataset-audit.md](todo/T-2.1-dataset-audit.md)
  - Status: READY
```

---

## Phase 3 — Assign skills and rules

For every existing document inside `./todo/`:

- assign **minimum necessary** skills (discover from `.cursor/skills/` metadata);
- assign **all relevant** rules (discover from `.cursor/rules/`);
- confirm inputs, outputs, environment, resource estimates if present.

Update the subtask document (`<Task>` Skills/Rules and Execution metadata). Do not invent new task IDs.

Do not assign unnecessary skills.

### Subtask metadata block

```markdown
## Execution metadata

| Field | Value |
|-------|-------|
| Task ID | T-2.1 |
| Skills | `@dataset-auditor` |
| Rules | validation-first, missing-data-policy |
| Inputs | `data/metadata/`, `data/raw/` |
| Outputs | `docs/dataset-audit.md` |
| Depends on | T-1.1 |
| Parallel with | — |
| Environment | local |
| Status | READY |
```

---

## Phase 4 — Optimize execution order

**Consume** the `@verify-todo` dependency graph (waves, parallel branches, terminal/blocking tasks).

Optimize for `@do`:

- map Phase 3 skill assignments onto graph waves;
- mark parallelizable READY tasks within the same wave;
- note optional / SKIPPED tasks;
- define checkpoints after critical waves;
- respect resource-aware batching hints for `@do` (throughput over agent count) without launching jobs.

**Do not** invent edges or re-validate the graph.

Summarize in `prepare-report.md` — link to `dependency-graph.mmd`; do not duplicate a second Mermaid source of truth.

---

## Phase 5 — Prepare execution plan + report

Generate:

`prepare-report.md`

Prefer `docs/prepare-report.md`. Template: [prepare-report-template.md](prepare-report-template.md).

Include:

- project summary
- execution graph summary (consumed from verify-todo)
- planned execution order (optimized waves)
- parallel execution opportunities
- assigned skills
- applied rules
- detected inconsistencies / orphans
- unresolved blockers
- expected outputs
- recommended next action (`@do`)

Register the report in `artifact-registry.md`.

---

## Phase 6 — Readiness validation

Verify:

- every existing todo item has a `./todo/` spec (no new tasks created here);
- every subtask has skills and rules assigned;
- metadata is complete for each wave;
- execution plan cites verify-todo graph artifacts;
- `@verify-todo` exit status was success.

**Do not** re-check cycles, missing dependency IDs, or graph connectivity.

If readiness fails because tasks are missing → stop and point to `@prepare-prompt`.

---

## Execution rules

- Never generate new tasks (that is `@prepare-prompt`).
- Never execute computational analyses or project tasks.
- Never run pipelines.
- Never modify source code.
- Never perform scientific analyses.
- Always consume the dependency graph from `@verify-todo`.
- Only prepare the project for execution.
- Produce a plan suitable for `@do`.

Allowed writes: `todo.md` (sync/links/status only), `./todo/**/*.md` (metadata/skills/rules only — no new files unless repairing a broken link to an existing path), `prepare-report.md` / `docs/prepare-report.md`, `artifact-registry.md` / `docs/artifact-registry.md`.

**Forbidden:** creating new `todo/T-*.md` task specifications for new work.

## Coordination

| Skill | Role |
|-------|------|
| `@prepare-prompt` | **Creates** `./todo/*.md` and links into `todo.md` — run before prepare when task files are missing |
| `@edit-prompt` | **Modifies** existing `./todo/*.md` — run before prepare when plan changes; then `@verify-todo` |
| `@verify-todo` | Builds/validates dependency graph — prepare **consumes** only |
| `@synchronize-todo` | Optional repo↔status sync |
| `@do` | Executes the prepare plan |
| `@generate-todo` | Authors main `todo.md` architecture — required before prepare-prompt when todo.md is missing |

## Artifact registration

Instead of creating standalone reports in arbitrary locations, require every generated artifact to be registered inside `artifact-registry.md` (prefer `docs/artifact-registry.md`).

Each registry entry must contain:

- artifact
- producer skill
- generation date
- purpose
- status
- downstream consumers

Every generated report, graph, manifest or checkpoint must be registered immediately after it is written.

Update existing rows when regenerating the same path; mark replaced paths `superseded`.

Format: [artifact-registry-template.md](../_shared/artifact-registry-template.md). Project rule: `artifact-registry` (alwaysApply).
